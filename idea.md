## Overview
A frontend-only web application that helps users discover and choose a name through
interactive, game-like modes. Each mode offers a different way to explore names, from
fast, instinct-based picking to more deliberate approaches.

## Modes

### 1. Quick Mode
The user finds their preferred name in 10 steps.

- Before step 1, the user chooses Boy, Girl or Any. This is a hard filter for the whole game: Boy shows male, mostly
  male and unisex names; Girl shows female, mostly female and unisex names; Any shows all names.
- Only names with at least 100 people (all spellings combined) can appear, to avoid obscure names (about 3,700 names).
- A name and all its spellings count as one name: only the most common spelling is shown, and once a name has appeared
  none of its spellings can appear again.
- In English, names are shown in their most common English spelling; in Hebrew, in Hebrew. Every eligible name has
  an English spelling in the data; if one is ever missing, the Hebrew spelling is shown instead.
- Before step 1, the user also chooses a difficulty, which sets the countdown for every step: Hard = 3 seconds,
  Normal = 5 seconds (default), Easy = 10 seconds.
- Each step shows 3 names and a countdown timer (length set by the difficulty).
- Step 1 shows 3 random names that have very little in common with each other.
- When the user selects a name, the next step shows the selected name plus 2 new names.
- The 2 new names must share at least one label with the last selected name, and are chosen by how much they have in
  common with all selections so far, with recent selections weighing more.
- Labels are weighted by rarity: a label shared by fewer names counts more (weight = log(total names ÷ names with that
  label)), with a cap so very small labels don't dominate. These weights are used both to narrow names in later steps
  and to keep step 1 names as different as possible.
- A name that has already appeared must not be shown again in the same session (except the selected name carried into
  the next step)
- If the countdown reaches zero without a selection, the same step repeats with 3 new names (the step count doesn't
  advance, and the carried-over name is dropped too). The new names follow the same narrowing rules, based on the
  selections so far; on step 1 they are again 3 names with very little in common. This also applies to step 10, so the
  game only ends when a name is selected in step 10.
- This repeats for 10 steps. The name selected in step 10 is shown full screen as the winner.
- The winner screen also shows the history of names selected in each step, with two buttons:
  - Restart: starts a new game with the same gender and difficulty.
  - Change gender: goes back to the Boy / Girl / Any choice, keeping the same difficulty.

## Tech stack

1. React + TypeScript. Component-based UI for the game screens (steps, countdown, winner), with type safety across
   names, labels and session state.
2. Vite. Dev server and build tool. It produces a static, frontend-only build with no server needed.
3. React Router. Routes for the home screen, each mode (/quick, later more), and the winner screen.
4. Zustand. State for the game session (current step, names already shown, selection history) and user settings
   (language, theme). Settings are saved in the browser.
5. i18next + react-i18next. All UI text in English and Hebrew, with switching on the fly. The name data already has
   both: Hebrew spellings, English spellings, and translated labels (labels.json / labels_he.json).
6. CSS Modules + CSS custom properties. Styling scoped per component, with one shared set of design tokens (colors,
   spacing, type, radius) for a consistent look across screens. Layout is mobile-first, using direction-aware properties
   (margin-inline-start, inset-inline-end) so Hebrew RTL flips automatically via <html dir>.
7. Theming with CSS variables. Light and dark token sets switched by a data-theme attribute. The default comes from
   prefers-color-scheme, and a manual toggle is saved in the browser. No library needed.
8. Motion (formerly Framer Motion). Game-like transitions: cards entering and leaving between steps, the countdown ring,
   and the full-screen winner reveal.
9. A plain TypeScript name-selection module, separate from the UI. It holds the Quick Mode logic:
    - step 1 picks 3 names with as few shared labels as possible;
    - later steps pick names that share labels with the selections so far, weighted toward recent picks, with rare labels
      counting more;
    - it tracks shown names so none repeat;
    - when the timer runs out, it falls back to 3 fresh names.
   Keeping it separate makes it easy to test and to reuse for future modes.
10. Static JSON data. Generated by the existing build script and split into a small startup index (names, labels,
    English spellings) plus yearly counts loaded only when needed.
11. Rubik via @fontsource. A self-hosted font that covers both Hebrew and Latin letters, so it works offline with no
    Google Fonts dependency.
12. Vitest. Unit tests for the selection logic: no repeats, the shared-label rule, step 1 diversity, and the timeout
    behavior.
13. Playwright. End-to-end tests on phone and desktop sizes, in both languages and both themes, including a full 10-step
    Quick Mode run.
14. ESLint + Prettier. Consistent code style.

## Mandatory Requirements
1. Full English and Hebrew support, including all UI text and the name data.
2. RTL layout support when Hebrew is active.
3. Mobile-first, fully responsive design.
4. A consistent visual style across all screens.
5. A dark/light theme toggle, defaulting to the system preference.
